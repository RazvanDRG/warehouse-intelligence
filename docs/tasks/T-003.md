# T-003: skip events that were already handled (processed_events)

Status: in review · Branch: task/T-003-processed-events · Risk: high (first database table and migration, new dependency, CI change, core Event contract)

## What we're building
WI remembers every event it has handled, in its own Postgres (never System 1's). When Kafka delivers the same event again (a commit lost to a rebalance, or a new KAFKA_GROUP_ID replaying every kept message), WI skips it, so no write happens twice.

## Done when
Each point is something you can see working, and the test that proves it.
- AC-1: `alembic upgrade head` creates processed_events (event_id text primary key, topic, partition, offset, processed_at with default now()); `alembic downgrade base` removes it; upgrading again works. (test: `tests/test_migrations.py::test_upgrade_downgrade_upgrade`)
- AC-2: first delivery: the handler runs, and its write plus the processed_events row are saved in one transaction. (test: `tests/test_idempotency.py::test_first_delivery_runs_handler_and_records_event`)

- AC-5: the Kafka offset is committed only after the transaction commits; a failed transaction commits no offset. (test: `tests/test_events.py::test_offset_committed_only_after_transaction`)
- AC-6: KafkaEventSource passes topic, partition and offset with each event; replaying the same messages through a new group handles each event once. (test: `tests/test_idempotency.py::test_replay_handles_each_event_once`)
