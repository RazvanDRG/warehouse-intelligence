# T-001: Repo skeleton with health endpoints, local stack and CI

- Status: in review
- Branch: task/T-001-repo-skeleton (from main)
- Risk: medium - new CI, dependencies and behavior across many files; no System 1 change, no tables

## Goal
The repo runs locally with one command and every push gets a green CI check, so later weeks build on a working base.

## Acceptance criteria
Each one is a behavior someone can observe, and the test that proves it.
- AC-1: `GET /ops/live` returns 200 `{"status": "ok"}` without touching any dependency. Test: `tests/test_ops.py::test_live_ok`
- AC-2: `GET /ops/ready` returns 200 when Postgres and Redis answer, and 503 naming the failing one when either is down. Tests: `tests/test_ops.py::test_ready_ok`, `tests/test_ops.py::test_ready_postgres_down`, `tests/test_ops.py::test_ready_redis_down` (dependencies faked, no real services)
- AC-3: folders `core/`, `adapters/warehouse/`, `api/`, `pipelines/`, `infra/` exist, and no module in `core/` imports `adapters`. Test: `tests/test_layout.py::test_core_does_not_import_adapters`
- AC-4: `infra/docker-compose.yml` defines api (8001), Postgres with pgvector (5433), Redis (6379), Prometheus (9090), Grafana (3000); no port clashes with System 1 (5432, 8000). Test: `tests/test_compose.py`
- AC-5: a multi-stage `Dockerfile` builds an image that starts the API. Test: CI `docker build` step
- AC-6: GitHub Actions runs ruff, pytest, `tools/boundary_check.py` and `docker build` on push and pull request, with no secrets and no LLM keys. Test: green workflow run
